Evaluation & Benchmarks
=======================

probejs ships with two evaluation frameworks and a curated set of benchmark
datasets for measuring detection accuracy.

.. contents::
   :local:
   :depth: 2

Overview
--------

The evaluation infrastructure lives under two locations:

==================================== ========================================================
Component                             Purpose
==================================== ========================================================
``evaluation/run_bench.py``           Runs probejs against standard benchmark datasets
                                      (SecBench.js, VulcaN) and computes recall.
``evaluate_regress.py``               Runs probejs against the in-tree regression suite
                                      (``tests/regress/``) and computes precision, recall,
                                      and F1 score.
``evaluation/explodejs-datasets/``    Pre-extracted benchmark cases from SecBench.js,
                                      VulcaN, and explode.js.
``bench_results.json``                Latest benchmark run results (generated by
                                      ``run_bench.py``).
==================================== ========================================================

Academic context (baseline tools, dataset provenance, and related work) is in
``evaluation/EvalJS.md``.

Benchmark Evaluation (``run_bench.py``)
---------------------------------------

``evaluation/run_bench.py`` runs probejs on a standard test corpus and reports
per-CWE recall.

Datasets
~~~~~~~~

Two datasets are available out of the box via the ``-D`` flag.  Both are
subsets of the `explodejs-datasets <https://github.com/formalsec/explodejs-datasets>`_
repository, pre-extracted under ``evaluation/explodejs-datasets/``.

evaluation. This dataset has no ground truth; it is used for measuring
analysis performance at scale rather than recall.

Usage
~~~~~

.. code-block:: bash

   # Run on SecBench (default)
   python3 evaluation/run_bench.py

   # Run on VulcaN subset
   python3 evaluation/run_bench.py -D vulcan

   # Run on a custom dataset directory
   python3 evaluation/run_bench.py -d path/to/dataset

   # Tune parallelism and timeout
   python3 evaluation/run_bench.py -j 4 -t 60

   # Disable JS-modeled built-in stubs
   python3 evaluation/run_bench.py --no-builtin-packages

Options
~~~~~~~

``-D <name>``
    Named dataset: ``secbench`` or ``vulcan``.

``-d <path>``
    Custom dataset directory path (overrides ``-D``).

``-j <N>``
    Parallel workers (default: CPU count).

``-t <seconds>``
    Timeout per case in seconds (default: 30).

``--no-builtin-packages``
    Disable JS-modeled stubs during evaluation.

Each case is a directory under ``<dataset>/<CWE>/<case-name>/`` containing
a ``src/index.js`` entry point. The script runs ``python -m probejs -t <vuln_type> -q
<file>`` for each case, detects whether a vulnerability is reported, and
aggregates results.

Output is written to ``bench_results.json`` in the project root.

Metrics
~~~~~~~

- **True Positive (TP)**: probejs correctly detected a known-vulnerable case
- **False Negative (FN)**: probejs did not detect a known-vulnerable case
- **Timeout**: Case exceeded the per-case timeout
- **Error**: Case crashed or could not be analysed
- **Recall** = TP / (TP + FN)

Regression Evaluation (``evaluate_regress.py``)
-----------------------------------------------

``evaluate_regress.py`` evaluates probejs against the in-tree test suite at
``tests/regress/``. Unlike the benchmark runner (which measures recall-only on
known-vulnerable cases), this script also measures **precision** by including
safe test cases that should not trigger detections.

Test Suite Structure
~~~~~~~~~~~~~~~~~~~~

The test suite is organised by purpose:

============================== ==============================================
Directory                       Contents
============================== ==============================================
``vulnerability_detection/``   Known-vulnerable patterns (recall tests)
``precision/``                 Safe patterns that should not trigger (precision tests)
``recall/``                    Additional recall-focused tests
``flows/``                     Complex / async flow tests
``BENCHMARK_METADATA_V3.json``  Metadata mapping CWEs, expected behaviours, and files
============================== ==============================================

Covers 6 CWE categories: CWE-78 (OS Command), CWE-79 (XSS), CWE-94 (Code
Execution), CWE-22 (Path Traversal), CWE-943 (NoSQL Injection), CWE-1321
(Prototype Pollution).

Full documentation: ``tests/regress/README_BENCHMARK.md``.

How It Works
~~~~~~~~~~~~

The script:

1. Discovers ``.js`` files under ``tests/regress/`` (skipping ``recall/`` and
   ``flows/`` subdirectories for focused evaluation).
2. Determines the vulnerability type from file name patterns and
   ``BENCHMARK_METADATA_V3.json``.
3. Determines expected behaviour from file name conventions:
   - ``*_safe.js`` or ``precision_*`` → expected **not vulnerable**
   - ``*vulnerable*`` → expected **vulnerable**
4. Runs ``python -m probejs -t <type> -q -m <file>`` on each file.
5. Classifies each result as TP, FP, TN, or FN.
6. Computes precision, recall, and F1 score per CWE and overall.
7. Writes ``evaluation_results.json``.

Usage
~~~~~

.. code-block:: bash

   python3 evaluate_regress.py

This runs probejs on every eligible file in ``tests/regress/`` and prints a
summary table:

::

   ===============================================
   PROBEJS PRECISION AND RECALL EVALUATION
   ===============================================
   Overall Results (N test files):
     True Positives (TP):   ... - Vulnerabilities correctly detected
     False Positives (FP):  ... - Safe code incorrectly flagged
     True Negatives (TN):   ... - Safe code correctly not flagged
     False Negatives (FN):  ... - Vulnerabilities not detected
   Metrics:
     Precision: ...%  (TP / (TP + FP))
     Recall:    ...%  (TP / (TP + FN))
     F1 Score:  ...

   Per-CWE Breakdown:
     CWE-XX:
       TP: X, FP: X, TN: X, FN: X
       Precision: ..., Recall: ..., F1: ...

Metrics
~~~~~~~

- **True Positive (TP)** — Vulnerable code correctly detected
- **False Positive (FP)** — Safe code incorrectly flagged
- **True Negative (TN)** — Safe code correctly passed
- **False Negative (FN)** — Vulnerable code missed

+---------------+---------------------------------------------------+
| Metric        | Formula                                           |
+===============+===================================================+
| **Precision** | TP / (TP + FP) — how many findings are real       |
+---------------+---------------------------------------------------+
| **Recall**    | TP / (TP + FN) — how many vulnerabilities found   |
+---------------+---------------------------------------------------+
| **F1 Score**  | 2 × (Precision × Recall) / (Precision + Recall)   |
+---------------+---------------------------------------------------+
